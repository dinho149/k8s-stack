# Service contract (infra ↔ services)

What `infra/teleport/src/components/AccessServices.ts` deploys and what each service expects.

## Namespace `teleport-access`

| Deployment | Image | Containers | Port | Bot / role |
|---|---|---|---|---|
| `teleport-mcp` | `k8s-teleport/teleport-access` (`mcp --http :8080`) | tbot sidecar + service | 8080 (`/mcp`, `/healthz`, `/readyz`) | `teleport-mcp` / `svc-teleport-mcp` |
| `access-broker` | `k8s-teleport/teleport-access` (`broker`) | tbot sidecar + service | 8081 (`/v1/*`, `/healthz`, `/readyz`) | `access-broker` / `svc-access-broker` |
| `access-agent` (optional) | `k8s-teleport/access-agent` | service | 8082 | `access-agent` / `svc-access-agent` |
| `tbot-ci-harness` | tbot | tbot only, writes Secret `ci-harness-identity` | – | `ci-harness` / `svc-ci-harness` |

Every bot joins with the **kubernetes** join method; the `TeleportProvisionToken` allows exactly the pod's ServiceAccount
(`teleport-access:<bot>`). tbot writes a renewing identity to an in-memory `emptyDir` at
`/var/run/teleport/identity/identity`; the Go service reads it with `NewDynamicIdentityFileCreds` and reloads on change.

## Environment (Go services, `TA_*`)

| Variable | Meaning |
|---|---|
| `TA_TELEPORT_ADDR` | auth service address (`teleport-cluster-auth.teleport.svc.cluster.local:3025`) |
| `TA_TELEPORT_IDENTITY_FILE` | identity file written by tbot |
| `TA_TELEPORT_INSECURE` | `true` only on kind |
| `TA_TELEPORT_EDITION` | `community` \| `enterprise` |
| `TA_MCP_SHARED_TOKEN` | bearer token the agent presents to `/mcp` |
| `TA_MCP_POLICY_FILE` / `TA_BROKER_POLICY_FILE` | `/etc/teleport-access/policy.yaml` (ConfigMap `broker-policy`, rendered from the role catalog) |
| `TA_BROKER_API_TOKEN` | bearer token for the broker API |
| `TA_BROKER_WEBHOOK_SECRET` | HMAC secret for broker → agent events |
| `TA_BROKER_AGENT_WEBHOOK_URL` | `http://access-agent.teleport-access.svc.cluster.local:8082/v1/broker/events` (empty = no notifications) |
| `TA_BROKER_APPROVALS` | `setstate` (Community) \| `review` (Enterprise) \| `native` (disabled) |
| `TA_BROKER_MODE` | `watch` (default) \| `poll` |

Shared secrets live in Secret `access-services` (generated by Pulumi with `@pulumi/random`); read them with
`pulumi stack output mcpSharedToken --show-secrets`.

## MCP identity binding

The agent opens **one MCP session per chat user** and sends `Authorization: Bearer <shared>`, `X-Teleport-User` and
`X-Teleport-User-Email`. The server binds the principal to the session in middleware; no tool accepts an identity
argument (the agent refuses any tool schema that does). On stdio (Claude Code / Desktop) the principal is the local
operator (`TA_MCP_STDIO_USER` or the connected identity).

## Agent environment (TypeScript)

See `services/access-agent/src/config/schema.ts`. Chat credentials come from Secret `access-agent-chat`, filled from the
Pulumi secret object `teleport:chat` (`anthropicApiKey`, `slackBotToken`, `slackAppToken`, `slackSigningSecret`,
`teamsAppId`, `teamsAppPassword`, `teamsTenantId`, `gchatProjectNumber`, `gchatServiceAccountJson`).
